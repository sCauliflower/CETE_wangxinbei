# 场景想定文件规范（v2.0）

> 目标：一个 CMO 改编场景对应一组相互链接的文件；卡片承载背景、编成、挂载与阵位参数，P/V 矩阵与分项长表在公式阶段生成。本规范约定文件组成、卡片字段、报告小节与 P/V 结构，便于由 P/V 矩阵反查场景；规模档位、具体系数在批量阶段按需要确定，不在此写死。
> 公式依据：`装备参数与场景想定\WTA_毁伤概率与价值公式.md`（第 4 节毁伤概率、第 5 节目标价值）。

## 1. 目录与命名

- 目录：`CommandModernOperations数据\生成场景想定\<批量目录>\`，P/V 产物置于其下 `P_V\`。
- 文件名：`<场景编号>_<英文短名>.json`，编号批量阶段统一分配；同一场景所有文件共用该编号。
- 一个场景一组文件，禁止跨场景合并。

## 2. 一组场景文件

| 文件 | 内容 |
| --- | --- |
| `<cid>_card.json` | 叙述层 + 双方编成、挂载、阵位全部参数 |
| `<cid>_场景想定报告.docx` | 中文叙述报告，小节与参数列见第 3 节 |
| `P_V/<cid>_pv.json` | 赛方规范 `P` 矩阵、`v` 向量、行列 `uid` 顺序与口径元数据 |
| `P_V/P_long_<cid>.csv` | 每对(红方单位, 蓝方目标)一行的分项因子链（可选，需要逐对反解时落） |
| `P_V/V_<cid>.csv` | 每个蓝方目标一行的价值分量 |
| `P_V/P_<cid>.csv` | 带红蓝单位表头的概率矩阵（人工核对用，与 `pv.json` 同源） |

## 3. 场景报告小节规范

报告按以下六个小节组织。叙述性小节（背景、任务目标、态势综述）只要求信息到位，不规定措辞与篇幅；参数性小节的列项与取值口径固定，须与卡片 JSON 一致。

### 3.1 一、场景基本信息

两列表（项目 / 内容），固定项目：场景编号、原始场景文件、场景年代、地域、历史时期、红方定位、蓝方定位、原文阵营写法、交战时间、交战海域/地点、海况、天气、环境备注、复杂度/难度、数据库版本。库内或正文取不到的项填 `—`，不留空行。

### 3.2 二、战争背景

中文叙述：交代冲突由来、改编方向、双方所处的大致态势。背景素材来自原始场景正文译写，不要求固定句式；与后续编成、任务目标保持一致。

### 3.3 三、双方任务目标

分红方（防守方）、蓝方（进攻方）各列一条任务意图，写明各自要达成的作战目的。

### 3.4 四、双方编成与装备参数

先一段总述：编入单位总数、红蓝数量、参数来源口径（型号/DP/RCS/探测距离/挂载取自装备库，阵位为示例重建），并说明编入挂载仅保留库内命中（resolved）武器。

红、蓝双方分别按机型 / 舰型分组列表。

**单位表列**：编号、型号、国别、DP、年份、机动 g、RCS 前向(m²)、雷达(nm)、ESM(nm)、阵位(x/y/高度)。舰艇无机动 g / 雷达 / ESM 值填 `—`；阵位写 `x=…，y=…，h=…`。

**挂载表列**：单位、武器编号、武器名称、类型、命中(空/海/陆/潜)、射程(空/海/陆/潜, nm)、数量。命中与射程按四类目标分列，无射程填 `—`；仅列库内命中武器。

### 3.5 五、战场部署与距离分布

先一段坐标系说明：x、y 单位海里（nm），高度单位米，单位间距离为平面欧氏距离（海里）；交战距离带与射程覆盖口径在此说明。

**部署表列**：单位、阵营、型号、x(nm)、y(nm)、高度(m)、对空射程(nm)、对海射程(nm)、对陆射程(nm)；无对应射程填 `—`。

表后给编队统计：红方编队中心、蓝方编队中心、双方编队间距，以及红—蓝单位间距的最小 / 均值 / 最大值。

### 3.6 六、对抗态势综述

叙述为主，分四块，数量与射程须与 3.4、3.5 的参数一致：

1. **总体态势**：年代地域、双方方位、编队中心与间距、所处交战距离带。
2. **红方防守部署**：单位总数、机型/舰型及各自数量、飞行高度、挂载武器型号、最大射程、防守任务。
3. **蓝方进攻部署**：同红方口径，写明突击兵力编成与进攻任务。
4. **距离与接战关系**：间距统计、按最大射程判定的覆盖关系、交战阶段划分；末尾可写推演顺序（前出 → 拦截 → 火力交换 → 近距/屏护对抗）。

> 报告不单设"装备线索清单""数据来源与局限"专章；来源口径与待标定项写进卡片 `provenance`。

## 4. 卡片 `*_card.json` 顶层字段

| 字段 | 类型 | 说明 | 来源 |
| --- | --- | --- | --- |
| `scenario_id` | string | 场景唯一编号，与 P/V 文件名一致 | 生成 |
| `schema_version` | string | 规范版本，固定 `2.0` | 固定 |
| `seed` | object | 原始 CMO 场景溯源信息 | .scen 纯文本字段 |
| `meta` | object | 想定叙述层：名称、年代、地域、阵营、环境、任务目标、背景正文 | 抽取 + 规则补全 |
| `provenance` | object | 各层数据来源与可信度、已知局限 | 生成 |
| `counts` | object | `red` / `blue` 单位数量 | 统计 |
| `units` | array | 单位编成与挂载（见第 5 节） | 装备库回填 + 示例重建 |
| `matrix_ref` | object | 指向 P/V 产物的文件名与行列方向说明 | 矩阵阶段回填 |

### 4.1 `seed` 溯源字段

`source_file`、`source_title`、`source_setting`、`source_year`、`source_complexity`、`source_difficulty`、`source_db_version`，逐项对应 .scen XML 头部纯文本字段。私有压缩块内不可得的内容留空，并在 `provenance.limitations` 注明。

### 4.2 `meta` 叙述字段

| 字段 | 说明 |
| --- | --- |
| `name` | 中文场景名（可附原名对照） |
| `year` | 想定年份（整数） |
| `region` / `period` | 地域、历史时期 |
| `sides.red` / `sides.blue` | 红方、蓝方称谓与定位（防守/进攻方向） |
| `sides_raw` | 原文阵营写法 |
| `date_time` / `location` / `playable_sides` / `duration` | 正文解析字段；解析不到留空 |
| `environment` | `sea_state`、`weather`、`notes` |
| `objective.red` / `objective.blue` | 双方任务目标，由背景正文归纳 |
| `background_zh` | 清洗译写后的中文背景叙述；英文原文不入卡片 |

### 4.3 `provenance` 来源标记

| 字段 | 取值约定 |
| --- | --- |
| `narrative` | `extracted_from_cmo_scen`：标题/背景/地域/年代/难度来自 .scen 纯文本 |
| `order_of_battle` | `rebuilt_from_db`：型号、DP、RCS、探测距离、挂载取自装备库；数量、阵位、挂载为示例重建 |
| `limitations` | 已确认拿不到或待标定的信息清单 |

## 5. 单位字段（`units[]`）

> `uid` 是矩阵行/列的键：红方 `R1…` 对应 `P` 行，蓝方 `B1…` 对应 `P` 列与 `v` 项；反推时先按 `uid` 取本行/本列单位，再取下列参数。

| 字段 | 说明 |
| --- | --- |
| `uid` | 单位编号，`R#` 红方、`B#` 蓝方 |
| `side` | `red` / `blue` |
| `role` | 角色：`fighter` / `surface_ddg` / `surface_ffg`，后续可扩 `sub`、`aew`、`sam` 等 |
| `kind` | 平台类别：`aircraft` / `ship` / `sub` / `facility` 等 |
| `platform_id` / `name` / `type` | 装备库编号、型号名、类型 |
| `target_class` | 目标类别，与角色对齐，供价值赋权与防护档位使用 |
| `nation` | 使用国家/阵营库内写法 |
| `dp` | 损害点数 |
| `year` | 服役年份 |
| `maneuver_g` | 机动评级/过载（评级到过载的映射待标定） |
| `rcs_em_m2` | E-M 波段前/侧/后向 RCS，`dbsm` 与 `m2` |
| `radar_max_nm` / `esm_max_nm` / `ir_max_nm` / `sonar_max_nm` / `visual_max_nm` | 各探测手段最大作用距离（海里） |
| `pos` | `rel_x_nm` / `rel_y_nm` / `alt_m` 相对阵位 |
| `jamming` / `aspect` | 干扰状态、进入方向 |
| `loadout` | 交战武器挂载（见第 6 节） |
| `support_stores` | 支援挂载（副油箱、加油吊舱等），不计入交战武器 |
| `mounts` | 舰艇安装的武器站/发射器配置名（未解析到武器编号前保留原文） |
| `resolved` | 平台是否在装备库命中；`false` 时参数为空 |

## 6. 挂载/武器字段（`loadout[]`、`support_stores[]`）

| 字段 | 说明 |
| --- | --- |
| `weapon_id` / `name` / `type` / `nation` | 武器库编号、名称、类型、国家 |
| `role` | 挂载角色（`strike` 等） |
| `qty` | 挂载数量 |
| `hit` | 对空/对海/对陆/对潜单发命中概率（0–1）；为 0 即不能打该类 |
| `range_nm` | 对空/对海/对陆/对潜射程区间 `[下限, 上限]`（海里），无射程为 `null` |
| `warhead` | 战斗部原始记录（库内字典，键名标类型） |
| `note` | 库内挂载角色备注 |
| `resolved` | 武器是否在装备库命中 |

## 7. P/V 产物 `<cid>_pv.json`

### 7.1 顶层字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `scenario_id` | string | 与卡片一致 |
| `red` / `blue` | int | 红方行数、蓝方列数 |
| `red_units` | array[string] | 行顺序的红方 `uid`，与卡片 `side=red` 同序 |
| `blue_units` | array[string] | 列顺序的蓝方 `uid`，与卡片 `side=blue` 同序；与 `v` 同序 |
| `P` | array[array[float]] | 概率矩阵，`P[i][j]` 为第 `red_units[i]` 单位对第 `blue_units[j]` 目标的单发毁伤概率 |
| `v` | array[float] | 价值向量，第 `j` 项对应 `blue_units[j]` |
| `meta` | object | 口径说明（概率口径、价值口径、行列方向、所用权重与截尾、因子取值备注、来源场景） |

### 7.2 分项长表

- **概率长表 `P_long_<cid>.csv`**：每对一行，列含 `red_uid, target_id, weapon_id, weapon_name, target_type, distance_nm, Rmax_nm, rho, Pk0, fR, fT, fG, fJ, fE, fK, p_ij, qty, type_match`。
- **价值长表 `V_<cid>.csv`**：每目标一行，列含 `target_id, target_name, target_class, DP, year, S_DP, R, G, Th, C_cov, z, v_j, v_norm`。

矩阵由长表按 `(red_uid, target_id)` 透视还原；元数据注明概率口径（毁伤/命中）、价值区间与所用系数版本。

## 8. 由 P/V 反查场景的对应关系

1. **矩阵可直接还原**：双方单位数量与行列 `uid` 顺序；目标价值分量；每对的武器、距离、射程比与分项因子；概率与价值口径。
2. **需回装备库补全**：平台原始参数（吨位、长度、CEP、完整传感器清单等）按 `platform_id` 分类别查库；武器原始参数按 `weapon_id` 查武器库。
3. **不可唯一反推**：`fR` 近距平坦段距离不唯一；价值线性加权混叠，单个 `v_j` 不能分离各分量；`fJ` 制导/干扰轮换以长表记录为准；待标定的 C 层系数（fK 形状因子、过载映射、隐身折减等）需外部约束；叙述层内容不在矩阵内，回到卡片 `meta` 与报告读取。
4. **闭环校验**：维度与行列 `uid` 同序；长表 `p_ij`/`v_j` 与矩阵逐格一致；用卡片参数按手册公式正算复核，偏差超阈值回查因子标定；抽取档场景按平台身份回放母场景子选取索引核对。

## 9. 与下游 WTA 阶段的衔接

1. 卡片只承载想定与参数；`P`、`v` 由矩阵阶段按公式生成，落 `P_V\` 目录。
2. 求解/分配阶段读取 `pv.json`：行武器分配、目标价值排序、齐射并集计算均以该文件为准。
3. 多武器齐射并集 `P_kill,j=1−∏(1−p_ij)` 在分配阶段计算，不写入单发概率矩阵。

## 10. 待确认规范点

- 舰载武器编号回填：从舰艇 `magazines`/`configurations` 解析到具体武器编号的规则。
- 地域同义名归一化表；装备线索按阵营二次归并。
- 机动评级到过载 `g` 的映射、特殊威胁 `Th` 与覆盖度 `C_cov` 的取值规则。
- `fR` 拐点、`fT/fG/fJ` 档位、`fK` 系数、价值权重与价值上下界、隐身 RCS 折减等 C 层经验值，待回放数据标定。
